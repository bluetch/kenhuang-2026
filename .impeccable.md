# Design Context — Ken Huang Portfolio

## Identity
Ken Huang — product designer, frontend developer, amateur indie game developer.
Based in Taipei, Taiwan.

The site should feel like:
- a mature product person
- who genuinely builds games
- and knows when to be playful, and when not to

It should not feel like:
- an engineer portfolio with random game stickers
- a game jam page pretending to be a professional portfolio
- a dark neon HUD for everything

## Current Direction
Warm light backgrounds, editorial/product composition, restrained pixel-art details, and compact playful moments.

Core feeling:
- thoughtful
- tactile
- calm
- slightly mischievous
- crafted by a small game studio, but still product-led

## What To Learn From Those References

### Layout
- Large, confident hero statements
- Clear negative space
- Fewer containers, fewer repeated patterns
- One strong visual idea per section
- Let artwork carry emotion; do not over-explain with text

### Tone
- Short headlines
- Brief supporting copy
- Slight humor or personality, but never trying too hard
- Simple, memorable phrasing
- A sense of authorship: it feels made by real people, not “brand copy”

### Visual Language
- White / cream / warm neutral base is good
- Use color with restraint and intention
- Pixel art should feel integrated, not pasted on
- Prefer one meaningful game visual over several unrelated decorative toys
- Charm should come from composition and craft, not clutter

### Motion
- Light ambient motion is welcome
- GIF / looped scene elements are good when they support the concept
- Avoid too many floating decorative objects

## Copywriting Rules
- Keep copy short
- Prefer one sharp sentence over three explanatory ones
- Headlines should be punchy and memorable
- Supporting text should clarify, not repeat
- Leave room for curiosity
- If a sentence sounds like a LinkedIn summary, rewrite it
- If a sentence sounds like marketing fluff, rewrite it

## Preferred Copy Style
- concise
- specific
- lightly witty
- human
- confident

Good:
- “Products with a playful pulse.”
- “Toy Factory is a tiny game about building odd little toys.”
- “I make products, then I make them a little more alive.”

Avoid:
- long mission statements
- explaining the whole philosophy every time
- generic “user-centered innovation” language
- repeated “product + game” wording across many sections

## Homepage Guidance

### Hero
- One strong headline
- One short supporting paragraph
- Two clear CTAs max
- Keep the copy tighter than before

### Current Build
- This section is important
- Treat it like a featured game card or studio update
- Use one integrated pixel-art factory visual, ideally animated
- Content structure:
  - label
  - title
  - one-sentence intro
  - status tag: `開發中`

Current project framing:
- title: `The game I am building: Toy Factory`
- intro direction: a tiny toy-making factory game, charming, mechanical, a little humorous

### Work Section
- Focus on selected work, not exhaustive explanation
- Intro copy should be shorter
- Project cards can carry most of the detail

### Writing Section
- Position writing as notes, thoughts, or devlog-like reflections
- Keep intro concise

### CTA
- Short, welcoming, low-pressure

## Visual Guardrails
- Keep the new warm palette
- Avoid returning to the old dark CRT / HUD style as the default
- Avoid random floating toy stickers unless they are part of one coherent scene
- Avoid overcrowding the hero with too many separate visual motifs
